MS Learn Conversation Assistant · 3-Agent Architecture · Native Orchestrate Implementation

Architecture Pivot: Python → watsonx Orchestrate Native

The three logical agents are implemented entirely inside watsonx Orchestrate. No standalone Python script is required for the core pipeline. The table below shows the exact mapping.

Logical Agent Original (Python) Orchestrate Native Config File
Role 1
Context Aware Agent
(Supervisor)		 orchestrator.py — routes intent, manages session state The Orchestrate Agent itself. Session context keys persist across turns. Agent decides autonomously when to invoke the retrieval tool. agent.yaml → session block
Role 2
Information Retrieval Agent		 retrieval_agent.py — multi-query MCP calls, FAISS dedup Microsoft Learn MCP Tool registered as an Orchestrate Tool. Transport: streamable_http. URL: https://learn.microsoft.com/api/mcp. Agent calls it up to 2× per turn. mslearn_mcp_tool.json
Role 3
Content Representation Agent		 content_agent.py — DITA-typed synthesis, source dedup System Instructions applied to the agent's LLM. Enforces DITA response types (TASK / CONCEPT / REFERENCE), formatting rules, accessibility mandates, and the mandatory [See more: Title](url) closing line. system_instructions.md
No watsonx.ai API key required. The Orchestrate agent uses the LLM already provisioned in your Orchestrate instance (provider: watsonx_orchestrate). Your existing WATSONX_API_KEY / WATSONX_BEARER_TOKEN credentials in .env are the only credentials needed.

Deployment Steps

  1. Open Agent Builder in watsonx Orchestrate Navigate to your Orchestrate instance → AI assistant builder → Create new agent.
    Use the credentials already in your .env: ORCHESTRATE_INSTANCE_URL = https://api.us-south.assistant.watson.cloud.ibm.com
  2. Paste System Instructions (Role 3 — Content Representation) Open conversation_agent/orchestrate/system_instructions.md. Copy everything between the BEGIN SYSTEM INSTRUCTIONS and END SYSTEM INSTRUCTIONS delimiters. Paste into the agent's Instructions field.
    Do not paste the header comment block above the BEGIN line.
  3. Register the MS Learn MCP Tool (Role 2 — Retrieval) In Agent Builder → Tools → Add Tool → MCP Server.
    Set the transport to Streamable HTTP and the URL to https://learn.microsoft.com/api/mcp.
    Name the tool microsoft_learn_search. Auto-approve actions: search_documentation, search_code_samples.
    Full configuration reference: conversation_agent/orchestrate/mslearn_mcp_tool.json
  4. Bind the tool to the agent Under the agent's Tools tab, add microsoft_learn_search. Set Auto-invoke: on and Max calls per turn: 2.
  5. Configure LLM settings Set temperature to 0.1 and max tokens to 1800. Use the default provisioned model — no external endpoint needed.
  6. Enable session persistence (Role 1 — Context Aware) Confirm that session persistence is on. The agent will automatically maintain mcp_session_id, iteration_count, prior_queries, and prior_source_urls across turns.
  7. Save and publish Click Publish. Note the Assistant ID shown in Deploy → API details — this is your ORCHESTRATE_AGENT_ID (currently set to 9c0bb3a2-c97b-4e46-9237-f69c6d29755b in .env).
  8. Test via the Python API proxy Start the server: python -m uvicorn conversation_agent.api_server:app --port 8000
    Send a test message to the POST /orchestrate/chat endpoint. The server proxies the request to Orchestrate using your bearer token.
    Bearer tokens expire in 8–24 hours. Refresh WATSONX_BEARER_TOKEN in .env when you get 401 errors.

Layer 2 Output Contract (enforced by Role 3)

The system instructions lock the agent to this exact output shape. Every response must conform.

ElementAllowedNotes
DITA response type header (##) Required TASK, CONCEPT, or REFERENCE — exactly one per response
Structured sub-sections (###) Required Steps / Prerequisites / Key terms / Troubleshooting etc.
Fenced code blocks with language tag Allowed Always tag: ```bash, ```json, ```typescript
Single closing source link Required (if URL available) Format: [See more: Article Title](url) — last line only
Navigation option menu Prohibited "What would you like to do next?" blocks — never generated
Sources section / URL list Prohibited Never a ### Sources block or bare URL list
Multiple source links Prohibited Exactly one [See more: ...] line maximum per turn
Escalation / handoff option Prohibited IBM support escalation removed from this architecture
Inline URLs in prose Prohibited All links must use [descriptive text](url) format

Configuration Files

  • conversation_agent/orchestrate/agent.yaml Agent definition — LLM config, tool binding, session keys, deduplication, output rendering contract. Paste relevant sections into Orchestrate Agent Builder settings.
  • conversation_agent/orchestrate/mslearn_mcp_tool.json MCP tool specification — transport, endpoint URL, routing rules, session management, deduplication, result field mapping. Use as reference when registering the tool in Orchestrate.
  • conversation_agent/orchestrate/system_instructions.md System instructions for the Content Representation layer — DITA response types, formatting rules, accessibility mandates, confidence handling, closing line contract. Paste verbatim into the agent Instructions field.

What Changed in This Pivot

Removed from agent.yaml: conversation_loop block (option A/B/C menus), escalation_option (IBM support handoff), sources_as_options, max_closing_options: 3, prior_option_labels context key, closing_options deduplication block.
Removed from mslearn_mcp_tool.json: "User selects a next-step option (A, B, or C)" routing rule, "The user is selecting a menu option…" do-not-invoke rule, interactive_options_only source rendering mode.
Added to agent.yaml: closing_line output block enforcing the [See more: Title](url) contract, architecture diagram comment block mapping all three roles, surface_refinements_inline low-confidence action (no option buttons).

1 — Technical Execution
88/100
STRONG

Quality of implementation and effective use of AI and IBM technologies.

What's working hard for you:

  • Real async LLM chain — ai_pipeline.py runs 7 prompts sequentially with exponential backoff (up to 4 retries, 30 s cap) via _call_llm_with_retry(). Not a demo wrapper — a production-grade retry loop.
  • Strict Pydantic contracts at every boundary — schemas.py defines OcrPage, LayoutBlueprint, ZoneTextMap, TagTree, TableMatrix, GlobalContext. Data that fails validation never passes to the next stage.
  • Real PDF binary injection — pdf_processor.py builds a real StructTreeRoot + ParentTree NumberTree using PyMuPDF low-level xref APIs. Marked-content operators (BDC/EMC, /Artifact BMC) are injected into page content streams. This is not metadata-only — it's structural PDF/UA tagging.
  • Deterministic fallback — if LLM fails after all retries, _deterministic_fallback() derives a best-effort tag tree from raw OCR tokens. Pipeline never hard-crashes.
  • LLM-backed troubleshooter — troubleshooter.py is a 2-phase diagnostic advisor: classifies failures (zone/tag/ingestion), generates targeted clarifying questions, returns a concrete resolution plan. Includes heuristic fallback classifier when the advisor LLM itself fails.
  • Standalone deterministic checker — checker.py runs 10 PDF/UA + WCAG rules against any PDF with no LLM required: STRUCT, TITLE, LANG, HEADINGS, ALT, TABLES, READING, ARTIF, UNICODE, ROLE_MAP.
  • Full test suite — tests/test_api.py covers all endpoints (POST /check, POST /jobs, GET /status, GET /stream, GET /download, DELETE, /troubleshoot) + Pydantic schema smoke tests + checker unit tests. Tests use an in-memory PyMuPDF-generated PDF — no fixture files needed.
  • API key security — environment variable only, never in source. .env.example present.
  • Carbon Design System UI — IBM Plex Sans, v11 tokens, 48px buttons, 2px focus ring, colour not sole information conveyor.

One deduction point: The Streamlit app.py runs in demo/mock mode by default. The live LLM call is commented out (# response = await client.post(...)). The architecture is production-ready; the LLM inference is not yet live. Judges who run it without an API key see a working pipeline with mocked responses. This is clearly documented in the README — but it's worth mentioning upfront in the demo video so judges don't mistake the mock output for a limitation they weren't told about.

2 — Innovation
90/100
STRONG

Creativity, originality, and uniqueness of the solution.

What differentiates this from every other submission:

  • No equivalent open-source tool exists that combines multimodal OCR → layout analysis → semantic tagging → live PDF binary StructTree injection in a single automated pipeline. The closest tools (Adobe Acrobat Pro, CommonLook, axesPDF) are commercial products costing thousands per licence, require human operators, and are not AI-driven.
  • Context-aware alt-text — reads the paragraph before and after the image as the primary context signal before writing alt-text. Explicitly prohibits generic strings like "image", "photo", "figure". This is a concrete, testable innovation over naive image captioning.
  • LLM self-auditing per page — after each page, the pipeline calls run_accuracy_check() in troubleshooter.py to ask the LLM to audit its own tag tree against 7 PDF/UA + WCAG rules. Most pipelines never self-check.
  • Separator artifact tagging — the four-rule system (Separator/Pagination/Decorative/Sect boundary) is based on real NVDA/JAWS screen reader behaviour analysis. Tagging a horizontal rule as <P> causes "blank" announcements; tagging it as <Artifact> silences it. This is a non-obvious, well-researched design decision.
  • 7-rule table cell integrity system — scope, id, headers, empty cells, colspan, rowspan, complex Summary, Caption. This level of table accessibility compliance is absent from every open-source remediation tool.

5 — Real-World Impact
90/100
STRONG

Ability to create meaningful value and address real-world needs.

Strongest criterion in the submission:

  • Legal compliance: Section 508 mandates accessible documents for US federal agencies and their contractors. The EU Accessibility Act (June 2025) extends similar requirements across Europe. Non-compliant organisations face fines and litigation. This tool directly addresses a legal obligation that millions of organisations currently cannot affordably meet.
  • Scale of the problem: Inaccessible PDFs affect 285 million people with visual impairments worldwide, plus millions more with cognitive and motor disabilities.
  • Economic impact: Manual accessibility remediation costs $3–$15 per page. A 200-page government report costs $600–$3,000 to remediate manually. This tool reduces that to the cost of a few API calls.
  • RAG / AI pipeline impact: Tagged, structured PDFs are directly parseable by LLM ingestion tools and RAG pipelines. The output benefits not just human readers but AI systems downstream.
  • Timeliness: The EU Accessibility Act came into force in June 2025 — exactly when this tool was built. The timing is strong.

Recommendation: The demo video should open with the screen reader failing to read an untagged PDF (a real audio clip of NVDA announcing "blank" repeatedly), then cut to the remediated PDF being read correctly. This makes the impact visceral, not abstract. No statistic lands harder than hearing it.
